# План ревью code-channel и вывода Claude SDK из эксплуатации

База ревью — main, 2a7bf54. Цель — один понятный путь исполнения: code-channel запускает OpenCode CLI. Архив сохраняет исходник старого исполнителя, его тест и рецепт. Состояние сервера, журналы и ключи в архив не входят.

## Очерёдность и критерии

| Приоритет | Ответственный | Критика и основание на базовой ревизии | Проверка и ожидаемый результат |
|---|---|---|---|
| P0 | Разработчик маршрутизатора | Решение о запуске распределено между конфигом, сохранённым active и кодом. В bin/code-channel:325 явный sdk запускает Claude, а на строках 413–445 auto выбирает запасного исполнителя даже без второго запроса оператора. Отключение записи в JSON оставляет ветку перехода в коде. | На подставном OpenCode пройти go, auto, audit и delivery; проверить прямой sdk, use sdk, старый active и отказ OpenCode. Поддерживаемые формы вызывают только OpenCode. Старые команды получают ошибку до старта исполнителя, ошибка auto не разрешает запуск другого движка. |
| P0 | Владелец интеграции | Профили developer и audit в config/opencode-channel.json читают промпт из каталога выводимого инструмента. Независимые команды зависят от одного удаляемого пути. | Перенести промпт без изменения байтов. Для каждого профиля разрешить путь относительно конфига и сверить содержимое. Переместить отслеживаемые исходники в архив вне bin, убрать права исполнения у архивных команд. Проверить справку, реестр и инструкции агента. |
| P1 | Ревьюер контроля изменений | cc_scope_check (bin/code-channel:97–111) сравнивает имена изменённых файлов. Если файл до запуска уже изменён, дополнительная запись в него не добавляет имени. У auto (строки 393–408) чужая правка может удовлетворить критерию непустого результата. | В одноразовой рабочей копии подготовить чужую правку. Проверить два отдельных случая: исполнитель ничего не сделал; исполнитель дописал в уже изменённый файл вне Files. Сравнить содержимое до и после и проверить код возврата. Совпадение имени файла не доказывает авторство. |
| P1 | Ревьюер журналирования | reconcile (bin/code-channel:200–221) при отсутствии title ищет последнюю сессию проекта по времени, отдельно читает идентификатор и пишет журнал до сверки. Поле rc в журнале может расходиться с итогом обёртки. | На локальной базе-фикстуре создать две сессии одного проекта с разными моделями. Сверить сессию, фактическую модель, статус процесса, код теста и итоговый код обёртки. Принять доказательство только при однозначной привязке к одному запуску. |
| P1 | Тимлид процессов | Старый permit создавался после отказа двух исполнителей и использовался Claude-хуком bin/goal-gate:13–34. Подмена недоступной второй проверки синтетическим кодом расширила бы полномочия. | Проверить, что отказ OpenCode не создаёт permit и устаревшая запись не превращает отказ в новый доступ. Отдельно проверить обработку SIGTERM, таймаута и конкурирующего запуска: lock освобождается после завершения, действующий владелец сохраняет lock. |

Офлайн-проверка критерия P1 воспроизвела обе ошибки в изолированном Git-репозитории: auto вернул 0 при пустом запуске поверх чужой правки; go вернул 0 после записи подставного исполнителя в уже изменённый файл other вне списка Files. Оба случая требуют исправления до использования кода 0 как доказательства выполненной работы. Проверка привязки сессии и жизненного цикла блокировки остаётся в плане последующего ревью. В этой поставке меняется только вывод SDK из эксплуатации и непосредственно зависимые интерфейсы.

## Выполнение текущего изменения

1. Изолировать изменения от активной рабочей копии. Сохранить оригинальные SDK-файлы в archive/sdk-agent, вынести общий промпт в config/code-channel-system-prompt.md.
2. Удалить ветки исполнения SDK, актуализировать конфиг, активные подсказки и документацию. Сохранить go, audit, auto, delivery и выбор разрешённой модели OpenCode.
3. Прогнать офлайн bin/code-channel-test, bin/code-channel-use-test и затронутые тесты хуков на фикстурах. Сверить архив с базовой ревизией и проверить git diff --check. Запуски внешних моделей для приёмки не нужны.
4. Проверить отдельно подготовленную ветку, публикацию через согласованный публичный PR в arwox-labs/tools и состояние установленной команды. Установка требует согласования с незакоммиченными изменениями рабочей копии. Откат — обратить только коммит этой задачи.

Основание для атрибуции — bin/sdk-agent:7 задаёт исполняемый файл claude из пакета claude_agent_sdk. Anthropic описывает этот пакет в [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview).

# Атом dcfg-m2wn (шаг 3): детект по факту правок + запрет подключать навыки

Файл один: `bin/codex-role` (репозиторий `/root/workspaces/tools`). Никаких git-коммитов: коммит и PR делает лид.

## Привязка

Твой атом: **`dcfg-m2wn`**. Книговодство ведёт лид: не вызывай `bd`, не создавай Goal, не запускай git (кроме `git -C … status --porcelain`, который входит в саму правку). В конце артефакта укажи `atom=dcfg-m2wn`.

## Две причины отказа, подтверждённые прогонами

1. Текстовые маркеры ловят собственный отчёт: артефакт с цитатой `read-only file system` дал `refusal=1` при `GATE: PASS`.
2. Прогон упал с «LFG требует `references/input-triage.md`, но такого файла в установленном навыке нет»: навык `/root/.codex/.tmp/marketplaces/compound-engineering-plugin/skills/lfg` ссылается на отсутствующий файл (в каталоге есть `intake.md`, но не `input-triage.md`). Исполнитель не стал подменять файл и не выполнил работу.

## Правка

1. Сними отпечаток дерева до запуска (для любой песочницы, дешево):
```
before=$(git -C "$project" status --porcelain --untracked-files=no 2>/dev/null | sha256sum | awk '{print $1}')
```
2. После прогона сними отпечаток снова. Логика приёмки:
   - `rc=0` и роль пишущая (`workspace-write`) и отпечаток не изменился → печатай строку RUNNER с `nochange=1` и `exit 1`;
   - текстовые маркеры (`Не могу|Остановился|read-only file system|^Отказ`) применяй ТОЛЬКО к `read-only` ролям, для пишущих они не используются вовсе.
3. В преамбулу `prompt` (там, где уже строка про книговодство) добавь ещё одну строку:
```
prompt+=$'\n\nНавыки и плагины не подключай: работай только по тексту этого задания. Если навык или правило ссылается на отсутствующий файл, это не повод останавливаться — выполни задание и упомяни отсутствие одной строкой в конце.'
```
4. Больше ничего не менять: строка запуска, таймауты, снапшот, наборы записи, формат остальных строк RUNNER.
